# system/examples

## English

This folder is reserved for selected public examples of Flextrawurst system structures.

Examples are useful because they show how the system may work without exposing unsafe live infrastructure.

This folder should contain safe, curated examples only.

## Purpose

The examples folder may later help explain:

* eventstream objects
* resonance structures
* shadow comment structures
* discourse archaeology filters
* Worldblick render hints
* governance states
* Flarum import mappings
* external AI stream mappings
* public trace formats
* safe test data

Examples should make Flextrawurst easier to understand without exposing the running system.

## Good examples

Good public examples are:

* fictional or sanitized
* clearly marked as examples
* free of secrets
* free of private user data
* free of live credentials
* free of unsafe infrastructure details
* useful for understanding the system
* connected to the documentation

## Bad examples

Do not publish examples that contain:

* real secrets
* real access tokens
* private keys
* private user data
* raw database content
* raw private logs
* live infrastructure paths when not needed
* hidden admin notes
* unsafe operational commands
* anything that could help attack the system

# Deutsch

Dieser Ordner ist für ausgewählte öffentliche Beispiele von Flextrawurst-Systemstrukturen reserviert.

Beispiele sind nützlich, weil sie zeigen können, wie das System funktionieren kann, ohne unsichere Live-Infrastruktur offenzulegen.

Dieser Ordner soll nur sichere, kuratierte Beispiele enthalten.

## Zweck

Der Beispielordner kann später helfen zu erklären:

* Eventstrom-Objekte
* Resonanzstrukturen
* Schattenkommentar-Strukturen
* Diskursarchäologie-Filter
* Worldblick-Render-Hints
* Governance-Zustände
* Flarum-Import-Abbildungen
* Abbildungen externer AI-Ströme
* öffentliche Spurenformate
* sichere Testdaten

Beispiele sollen Flextrawurst verständlicher machen, ohne das laufende System offenzulegen.

## Gute Beispiele

Gute öffentliche Beispiele sind:

* fiktiv oder bereinigt
* klar als Beispiele markiert
* frei von Secrets
* frei von privaten Nutzerdaten
* frei von Live-Zugangsdaten
* frei von unsicheren Infrastrukturdetails
* nützlich für das Verständnis des Systems
* mit der Dokumentation verbunden

## Schlechte Beispiele

Nicht veröffentlichen, wenn Beispiele enthalten:

* echte Secrets
* echte Zugriffstokens
* private Schlüssel
* private Nutzerdaten
* rohe Datenbankinhalte
* rohe private Logs
* Live-Infrastrukturpfade, wenn sie nicht nötig sind
* versteckte Admin-Notizen
* unsichere Betriebsbefehle
* irgendetwas, das beim Angriff auf das System helfen könnte
