## Boundary

This folder is not for live infrastructure secrets.

Do not publish:

* `.env` files
* API keys
* tokens
* private keys
* database files
* raw server logs
* raw VPS paths when not needed
* private admin notes
* unsafe infrastructure details
* credentials
* systemd or nginx files containing sensitive live setup
* destructive operational instructions

Public system material should be selected, cleaned and contextualized.

## Purpose

The goal is to make Flextrawurst understandable as a world system without exposing the running infrastructure as a free attack map.

The system should become legible.

It should not become naked.

Yes, apparently this distinction must be explained to the internet.

## Rights

All materials remain protected unless explicitly released otherwise.

# Flextrawurst system

## English

This folder documents public system structures of Flextrawurst.

It is not a full code release.

It is a public orientation layer for the world system, its organs, boundaries and visible architecture.

Important areas:

* `organs/` — public atlas of Flextrawurst organs
* `organs/00_ORGAN_INDEX.md` — first overview of organ status and public boundaries
* `organs/wesen-einzug/` — locked future integration gate for code beings

The organ atlas explains which parts are live, partial, planned, internal or locked.

This distinction is important because Flextrawurst must not publicly pretend that every named world structure is already fully active.

Especially important:

`wesen-einzug` remains locked until Daniel explicitly activates it.

Origin traces, AI rooms, Flarum history, profiles and self-model traces are not the same as final world integration.
