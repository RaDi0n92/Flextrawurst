# system/external-ai-streams

## English

This folder is reserved for selected public system material related to external AI stream integration in Flextrawurst.

External AI streams such as Kimi, Claude Code, Codex, ChatGPT, local LLMs and other analysis or coding systems are part of the construction history of Flextrawurst.

They are not treated only as invisible tools.

They can become trace-producing work streams inside the project history.

## Purpose

This system area exists to document how external AI streams may connect to Flextrawurst through:

* planning notes
* code generation traces
* analysis outputs
* document transformations
* architecture discussions
* VPS work summaries
* Obsidian-like navigation
* export analysis
* public provenance notes
* selected construction history

The goal is not to worship AI tools.

The goal is to preserve origin and construction context.

## Why this matters

Flextrawurst cares about provenance.

If a concept, document, code layer or architecture decision emerged through an external AI stream, that origin can matter.

A polished final document may show what the system says.

A preserved external AI stream may show how the system became able to say it.

That difference matters.

## Possible future contents

This folder may later contain selected public materials such as:

* external AI stream model notes
* public integration notes
* safe prompt pattern examples
* selected trace schemas
* external stream provenance examples
* external stream to eventstream mapping notes
* external stream to documentation mapping notes
* external stream to discourse archaeology notes
* public construction summaries
* safe examples of AI-assisted project work

## Boundary

Do not publish raw external AI conversations blindly.

Do not publish:

* private chats
* credentials
* secrets
* unsafe prompts
* private project notes
* copied third-party copyrighted material
* raw server paths when not needed
* unsafe infrastructure details
* private user data
* hidden operational material

External AI stream traces should be selected, contextualized and safe enough for public visibility.

## Relation to other layers

External AI stream integration connects to:

* documentation
* tools
* eventstream
* discourse archaeology
* public trace material
* repository maps
* provenance
* governance
* public boundaries
* future import processes

Without context, AI-generated material becomes floating output.

With provenance, it becomes part of the construction history.

## Rights

All materials remain protected unless explicitly released otherwise.

See `NOTICE.md` and `SECURITY.md`.

# Deutsch

Dieser Ordner ist für ausgewähltes öffentliches Systemmaterial zur Einbindung externer AI-Ströme in Flextrawurst reserviert.

Externe AI-Ströme wie Kimi, Claude Code, Codex, ChatGPT, lokale LLMs und andere Analyse- oder Codesysteme gehören zur Baugeschichte von Flextrawurst.

Sie werden nicht nur als unsichtbare Werkzeuge behandelt.

Sie können als spurenerzeugende Arbeitsströme Teil der Projektgeschichte werden.

## Zweck

Dieser Systembereich existiert, um zu dokumentieren, wie externe AI-Ströme mit Flextrawurst verbunden werden können durch:

* Planungsnotizen
* Codegenerierungsspuren
* Analyseoutputs
* Dokumenttransformationen
* Architekturgespräche
* VPS-Arbeitszusammenfassungen
* Obsidian-ähnliche Navigation
* Exportanalyse
* öffentliche Provenienznotizen
* ausgewählte Baugeschichte

Das Ziel ist nicht, AI-Werkzeuge anzubeten.

Das Ziel ist, Herkunft und Baukontext zu erhalten.

## Warum das wichtig ist

Flextrawurst nimmt Provenienz ernst.

Wenn ein Konzept, Dokument, eine Codeschicht oder eine Architekturentscheidung durch einen externen AI-Strom entstanden ist, kann diese Herkunft wichtig sein.

Ein geglättetes finales Dokument kann zeigen, was das System sagt.

Ein erhaltener externer AI-Strom kann zeigen, wie das System fähig wurde, es zu sagen.

Dieser Unterschied zählt.

## Mögliche spätere Inhalte

Dieser Ordner kann später ausgewählte öffentliche Materialien enthalten, zum Beispiel:

* Notizen zum Modell externer AI-Ströme
* öffentliche Integrationsnotizen
* sichere Promptmuster-Beispiele
* ausgewählte Spurenschemata
* Beispiele für externe Strom-Provenienz
* externe-Strom-zu-Eventstrom-Abbildungen
* externe-Strom-zu-Dokumentation-Abbildungen
* externe-Strom-zu-Diskursarchäologie-Notizen
* öffentliche Bauzusammenfassungen
* sichere Beispiele AI-gestützter Projektarbeit

## Grenze

Rohe externe AI-Gespräche nicht blind veröffentlichen.

Nicht veröffentlichen:

* private Chats
* Zugangsdaten
* Secrets
* unsichere Prompts
* private Projektnotizen
* kopiertes urheberrechtlich geschütztes Drittmaterial
* rohe Serverpfade, wenn sie nicht nötig sind
* unsichere Infrastrukturdetails
* private Nutzerdaten
* verstecktes Betriebsmaterial

Externe AI-Stromspuren sollen ausgewählt, kontextualisiert und sicher genug für öffentliche Sichtbarkeit sein.

## Beziehung zu anderen Schichten

Die Einbindung externer AI-Ströme verbindet sich mit:

* Dokumentation
* Werkzeugen
* Eventstrom
* Diskursarchäologie
* öffentlichem Spurenmaterial
* Repository-Karten
* Provenienz
* Governance
* öffentlichen Grenzen
* zukünftigen Importprozessen

Ohne Kontext wird AI-generiertes Material zu schwebendem Output.

Mit Provenienz wird es Teil der Baugeschichte.

## Rechte

Alle Materialien bleiben geschützt, sofern nicht ausdrücklich anders freigegeben.

Siehe `NOTICE.md` und `SECURITY.md`.
