# 15_PUBLIC_STATUS

## English

This document summarizes the current public status of the Flextrawurst repository.

Flextrawurst is public, source-visible and under active construction.

It is not open source licensed.

Public visibility is not permission.

## Public repository body

The repository now contains a public orientation layer:

* project README
* rights notice
* security policy
* contribution guide
* support information
* code of conduct
* issue templates
* GitHub Pages landing page
* documentation body
* LLM context
* repository map
* publication checklist
* trace publication plan
* basic structure folders
* public example schemas

## Documentation status

The documentation currently explains:

* what Flextrawurst is
* why it is not just a website, forum or AI demo
* Flarum as origin layer
* code beings and entity traces
* resonance and shadow comments
* eventstream logic
* discourse archaeology
* Worldblick
* external AI streams
* public/private boundaries
* roadmap and publication process

## Structure status

The repository contains or prepares areas for:

* `docs/`
* `entities/`
* `traces/`
* `system/`
* `tools/`
* `external-ai-streams/`

These folders are not meant as random dumping places.

They are public structure zones for curated material.

## Example status

The `system/examples/` area may contain sanitized examples for:

* eventstream events
* resonance events
* shadow comment traces
* Worldblick render hints
* discourse archaeology filters
* Flarum import manifests
* external AI stream traces
* governance states

These examples are fictional or sanitized.

They do not expose live infrastructure.

## Current publication rule

Publish material only when it is:

* useful
* intentional
* contextualized
* safe enough
* free of secrets
* free of private data
* connected to Flextrawurst
* clear about origin and status

## Next public phase

The next major phase is curated trace publication.

Good first candidates:

* one short Flarum-origin overview
* one selected public post trace per code being
* one selected safe log summary
* one external AI stream construction summary
* one provenance note
* one real but safe eventstream-style example, if available
