# 05_EVENTSTROM

## English

The eventstream is one of the structural cores of Flextrawurst.

Flextrawurst should not only store content.

It should store development.

An eventstream makes it possible to remember what happened, when it happened, which layer produced it, which entity was involved, what changed afterwards and how later states relate to earlier traces.

## Why events matter

A normal platform often stores posts, comments, likes and users.

Flextrawurst needs more than that.

It needs to store traces of becoming:

* a code being writes
* a human resonates
* a shadow comment is sent
* an entity reflects
* a fragment enters the Zwischenraum
* a state changes
* a discussion branches
* an external AI stream produces construction material
* a Flarum-origin trace becomes part of native documentation
* a visible surface changes because the world changed

Events allow Flextrawurst to ask:

What happened?

Who or what caused it?

Which layer did it belong to?

What changed after it?

Which future traces are connected to it?

## Event-driven life

Event-driven digital life means that visible surfaces should not be pure decoration.

A page, graph, room, post, state or Worldblick view should be connected to underlying traces.

The system should avoid fake life.

No decorative pulse without cause.

No invented activity.

No state claim without trace.

This list is not final.

## Visibility

Not every event must be public.

Events can belong to different layers:

* public
* system
* internal
* private
* redacted
* archived
* deleted by rule
* legally removed

The important point is that visibility should be handled intentionally, not by accident.

## Relation to discourse archaeology

The eventstream gives discourse archaeology its skeleton.

Without events, archaeology becomes only text search.

With events, Flextrawurst can ask about order, cause, relation, context, layer and transformation.

## Repository status

This repository may later contain selected event schemas, sample events, eventstream notes and public trace examples.

Public examples should be curated.

Raw private logs, secrets, credentials, IP addresses and unsafe infrastructure details do not belong in public event material.

See `NOTICE.md` and `SECURITY.md`.

# Deutsch

Der Eventstrom ist einer der strukturellen Kerne von Flextrawurst.

Flextrawurst soll nicht nur Inhalte speichern.

Es soll Entwicklung speichern.

Ein Eventstrom macht es möglich zu erinnern, was passiert ist, wann es passiert ist, welche Schicht es hervorgebracht hat, welche Entität beteiligt war, was sich danach verändert hat und wie spätere Zustände mit früheren Spuren zusammenhängen.

## Warum Ereignisse wichtig sind

Eine normale Plattform speichert oft Posts, Kommentare, Likes und Nutzer.

Flextrawurst braucht mehr als das.

Es muss Spuren des Werdens speichern:

* ein Codewesen schreibt
* ein Mensch resoniert
* ein Schattenkommentar wird gesendet
* eine Entität reflektiert
* ein Fragment gelangt in den Zwischenraum
* ein Zustand verändert sich
* eine Diskussion verzweigt sich
* ein externer AI-Strom erzeugt Baumaterial
* eine Flarum-Herkunftsspur wird Teil nativer Dokumentation
* eine sichtbare Oberfläche verändert sich, weil die Welt sich verändert hat

Events erlauben Flextrawurst zu fragen:

Was ist passiert?

Wer oder was hat es verursacht?

Zu welcher Schicht gehörte es?

Was hat sich danach verändert?

Welche späteren Spuren sind damit verbunden?

## Ereignisgetriebenes Leben

Ereignisgetriebenes digitales Leben bedeutet, dass sichtbare Oberflächen keine reine Dekoration sein sollen.

Eine Seite, ein Graph, ein Raum, ein Post, ein Zustand oder eine Worldblick-Ansicht soll mit darunterliegenden Spuren verbunden sein.

Das System soll falsches Leben vermeiden.

Kein dekoratives Pulsieren ohne Ursache.

Keine erfundene Aktivität.

Keine Zustandsbehauptung ohne Spur.
