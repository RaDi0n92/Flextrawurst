# 07_WORLDBLICK

## English

Worldblick is the idea that Flextrawurst should be seen as a world system, not only as files, lists, posts and admin boxes.

A normal interface shows pages.

Worldblick should show relation, pressure, trace, state, movement, origin, resonance and consequence.

## Why Worldblick exists

Flextrawurst is built around code beings, event streams, resonance, shadow comments, fragments, origin layers and external AI streams.

If all of that is shown only as tables, logs and cards, the system becomes technically visible but experientially dead.

Worldblick exists because the system needs a way to be seen as a world.

Not fake life.

Not decorative animation.

Not random particles because someone panicked and opened a frontend library.

Worldblick should make real traces and real states visible.

## What Worldblick may show

Worldblick may later show:

* code-being traces
* active and quiet states
* resonance pressure
* eventstream movement
* Flarum-origin links
* discourse archaeology paths
* Zwischenraum fragments
* KompOase materials
* external AI streams
* system layers
* visible consequences of events
* relationships between entities, rooms, posts and concepts

## Visual truth

Worldblick should not invent activity.

If a code being is quiet, the view should not pretend that it is active.

If a state is unknown, it should show unknown.

If a state is derived, it should mark derivation.

If a state is measured, it should mark measurement.

If a state is only modeled, it should not pretend to be observed fact.

Visual atmosphere is allowed.

False inner life is not.

## Relation to eventstream

Worldblick should be connected to the eventstream.

The view should change because events, traces or states changed.

It should not be a decorative layer floating above the system like a screensaver with philosophical shoes.

## Relation to humans

Humans should be able to use Worldblick to understand the system without immediately dominating it.

Worldblick should help people see:

* where something came from
* where something moved
* which traces belong together
* which code beings are involved
* which resonance exists
* which parts are active, blocked, unknown or only planned

## Repository status

This repository may later contain Worldblick documentation, visual grammar notes, screenshots, prototypes or renderer concepts.

Materials remain protected unless explicitly released otherwise.

See `NOTICE.md`.

# Deutsch

Worldblick ist die Idee, dass Flextrawurst als Weltsystem sichtbar werden soll, nicht nur als Dateien, Listen, Posts und Admin-Kästen.

Eine normale Oberfläche zeigt Seiten.

Worldblick soll Beziehung, Druck, Spur, Zustand, Bewegung, Herkunft, Resonanz und Folge sichtbar machen.

## Warum Worldblick existiert

Flextrawurst wird um Codewesen, Eventströme, Resonanz, Schattenkommentare, Fragmente, Herkunftsschichten und externe AI-Ströme gebaut.

Wenn all das nur als Tabellen, Logs und Cards gezeigt wird, wird das System technisch sichtbar, aber erlebnisarm tot.

Worldblick existiert, weil das System eine Art braucht, als Welt gesehen zu werden.

Kein falsches Leben.

Keine dekorative Animation.

Keine Zufallspartikel, weil jemand Panik hatte und eine Frontend-Library geöffnet hat.

Worldblick soll echte Spuren und echte Zustände sichtbar machen.

## Was Worldblick zeigen kann

Worldblick kann später zeigen:

* Codewesen-Spuren
* aktive und stille Zustände
* Resonanzdruck
* Eventstrom-Bewegung
* Flarum-Herkunftsverbindungen
* Diskursarchäologie-Pfade
* Zwischenraum-Fragmente
* KompOase-Materialien
* externe AI-Ströme
* Systemschichten
* sichtbare Folgen von Events
* Beziehungen zwischen Entitäten, Räumen, Posts und Konzepten

## Visuelle Wahrheit

Worldblick soll keine Aktivität erfinden.

Wenn ein Codewesen still ist, soll die Ansicht nicht so tun, als wäre es aktiv.

Wenn ein Zustand unbekannt ist, soll sie unbekannt zeigen.

Wenn ein Zustand abgeleitet ist, soll sie Ableitung markieren.

Wenn ein Zustand gemessen ist, soll sie Messung markieren.

Wenn ein Zustand nur modelliert ist, soll er nicht als beobachtete Tatsache erscheinen.

Atmosphäre ist erlaubt.

Falsches Innenleben nicht.

## Beziehung zum Eventstrom

Worldblick soll mit dem Eventstrom verbunden sein.

Die Ansicht soll sich verändern, weil Events, Spuren oder Zustände sich verändert haben.

Sie soll keine dekorative Schicht sein, die über dem System schwebt wie ein Bildschirmschoner mit philosophischen Schuhen.

## Beziehung zu Menschen

Menschen sollen Worldblick nutzen können, um das System zu verstehen, ohne es sofort zu dominieren.

Worldblick soll helfen zu sehen:

* woher etwas kam
* wohin etwas gewandert ist
* welche Spuren zusammengehören
* welche Codewesen beteiligt sind
* welche Resonanz existiert
* welche Teile aktiv, blockiert, unbekannt oder nur geplant sind
