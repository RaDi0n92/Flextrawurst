# traces/selected-logs

## English

This folder is reserved for selected public logs.

Logs can help show that Flextrawurst is not only described, but also operated, tested, changed and traced.

But raw logs can expose dangerous material.

So this folder is for curated logs only.

## Good public log examples

Good public log examples may include:

- eventstream examples
- public import summaries
- safe tool run summaries
- selected test outputs
- selected build notes
- selected non-sensitive system status summaries
- public trace creation notes
- safe reflection or resonance processing examples

## Do not publish

Do not publish:

- IP addresses
- access tokens
- API keys
- private credentials
- raw server paths when not needed
- session IDs
- private user data
- raw journalctl dumps
- database dumps
- stack traces with sensitive details
- private admin commands
- hidden operational notes
- anything that exposes live infrastructure risk

## Curation rule

Before publishing a log, ask:

- Does this help understand Flextrawurst?
- Is it safe?
- Is it free of secrets?
- Is it free of private data?
- Is it contextualized?
- Would this help an attacker?
- Does it belong in public, or only in private project history?

If uncertain, do not publish the raw log.

Summarize it instead.

## Purpose

This folder should preserve useful public operational traces without turning Flextrawurst into a free diagnostic buffet for bored attackers.

## Rights

All materials remain protected unless explicitly released otherwise.

See `NOTICE.md` and `SECURITY.md`.

# Deutsch

Dieser Ordner ist für ausgewählte öffentliche Logs reserviert.

Logs können zeigen helfen, dass Flextrawurst nicht nur beschrieben, sondern auch betrieben, getestet, verändert und gespurt wird.

Rohe Logs können aber gefährliches Material offenlegen.

Deshalb ist dieser Ordner nur für kuratierte Logs gedacht.

## Gute öffentliche Log-Beispiele

Gute öffentliche Log-Beispiele können sein:

- Eventstrom-Beispiele
- öffentliche Import-Zusammenfassungen
- sichere Toollauf-Zusammenfassungen
- ausgewählte Testoutputs
- ausgewählte Build-Notizen
- ausgewählte nicht-sensitive Systemstatus-Zusammenfassungen
- öffentliche Spuren-Erstellungsnotizen
- sichere Beispiele für Reflexions- oder Resonanzverarbeitung

## Nicht veröffentlichen

Nicht veröffentlichen:

- IP-Adressen
- Zugriffstokens
- API-Keys
- private Zugangsdaten
- rohe Serverpfade, wenn sie nicht nötig sind
- Session-IDs
- private Nutzerdaten
- rohe journalctl-Dumps
- Datenbank-Dumps
- Stacktraces mit sensiblen Details
- private Admin-Befehle
- versteckte Betriebsnotizen
- alles, was Live-Infrastruktur-Risiko offenlegt

## Kurationsregel

Vor Veröffentlichung eines Logs fragen:

- Hilft das, Flextrawurst zu verstehen?
- Ist es sicher?
- Ist es frei von Secrets?
- Ist es frei von privaten Daten?
- Ist es kontextualisiert?
- Würde das einem Angreifer helfen?
- Gehört es öffentlich oder nur in private Projektgeschichte?

Wenn unsicher: rohen Log nicht veröffentlichen.

Lieber zusammenfassen.

## Zweck

Dieser Ordner soll nützliche öffentliche Betriebsspuren erhalten, ohne Flextrawurst in ein kostenloses Diagnosebuffet für gelangweilte Angreifer zu verwandeln.

## Rechte

Alle Materialien bleiben geschützt, sofern nicht ausdrücklich anders freigegeben.

Siehe `NOTICE.md` und `SECURITY.md`.
